# 파트 — 합의 (2026-10-14)

프로젝트 안을 파트(AI · 인프라 · 기간계 연동 …)로 나눈다. **목적은 노이즈를 줄이는 것이지 막는 것이 아니다.**
**2026-11-12 부터 파트 소속에 권한 넷(보기 · 등록 · 수정 · 삭제)이 붙는다** — 보기는 여전히 열려 있고, 등록 · 수정 · 삭제가 그 파트 **작업 · 테스트** 쓰기를 가른다. 안건은 타지 않는다('파트 권한 (2026-11-12)').
디자이너가 평소에 "서버 OS 결정" 을 볼 일은 없어야 하지만, 자기 작업이 그 결정에 걸리면 바로 보여야 한다.
순서는 `server/PLAN.md` 9단계 · `web/PLAN.md` 9단계다.

## 보기 규칙 — "내 파트"

화면 위쪽의 **[내 파트 | 전체]** 전환. 기본값은 **일반 사용자 = 내 파트**, **프로젝트 관리자 · 시스템 관리자 = 전체**.
고른 값은 프로젝트마다 브라우저에 기억한다. **내가 속한 파트가 하나도 없으면 전환을 숨기고 전체를 보인다.**

'내 파트' 에서 보이는 것:

**작업** — 아래 중 하나라도 맞으면
1. `partId` 가 `null`(공통)이거나 내가 속한 파트
2. 내가 담당자
3. 위 1 · 2 로 보이는 작업의 **조상** — 계층 경로 · 간트 트리가 끊기지 않게 (조상은 흐리게 그려도 된다)

**안건** — 아래 중 하나라도 맞으면
1. `partId` 가 `null`(공통)이거나 내가 속한 파트
2. 내가 담당자
3. **작업 규칙 1 · 2 로 보이는 작업에 링크로 걸린 안건** — 막힌 이유는 언제나 보인다.
   경로를 잇느라 선 조상(작업 규칙 3)의 링크는 끌어오지 않는다 — 남의 파트 묶음 아래 작업 하나를 맡았다고 그 파트의 결정이 다 딸려 오면 안 된다

- 규칙은 `web/src/lib/` 의 순수 함수 하나에 둔다. 목록 · 칸반 · 간트 · 안건 목록이 같이 쓴다
- 상세 화면을 주소(`/tasks/:id` · `/agendas/:id`(2026-11-04 전 `/threads/:id`))로 직접 열면 '내 파트' 여도 **연다** — 거르는 것은 목록이다
- 보관한 파트도 규칙은 같다(그 파트의 옛 작업은 그 파트 사람에게 계속 보인다)
- **볼 파트 고르기 (2026-11-11)** — `[내 파트 | 전체]` 전환을 담당자 고르기처럼 **파트 고르기** 하나로 바꿨다. 내가 속한 파트 중 여럿을 고르고(버튼은 '인프라' · '인프라 외 1'), **비우면(풀기 ×) 전체 파트**다. 위 규칙의 '내가 속한 파트' 자리에 고른 파트가 들어간다(공통 · 내가 담당 · 링크 규칙은 그대로). **처음은 누구나 전체**(위 '기본값' 줄을 갈음한다). 프로젝트 · 사람마다 브라우저에 기억하고(`innoflow.partPick.<memberId>.<projectId>`, 예전 `innoflow.partScope.…` 값은 새 값이 없을 때 이어받는다), 고른 파트에서 다 빠지면 내 파트 전부로 돌아간다. 화면만의 일이라 서버 · API 는 그대로다

## 파트 권한 (2026-11-12)

사용자 결정. 파트 소속(`part_member`) 하나에 체크 넷 — **보기(view) · 등록(create) · 수정(update) · 삭제(delete)**.
보기는 열려 있다 — 서버는 스냅샷 · 검색 · 챗봇에서 아무것도 숨기지 않는다. 등록 · 수정 · 삭제는 그 파트(`partId`)가 달린 **작업 · 테스트**의 쓰기를 가른다.
**안건은 파트 권한을 타지 않는다** — 파트를 넘나드는 협의가 안건의 일이라 규칙은 예전 그대로(`auth.md` '안건')다.

### 맞추기 — 서버가 쓸 때마다

**삭제 ⇒ 수정, 등록 또는 수정 ⇒ 보기.** 딸린 것을 **위로 켠다**(끄는 쪽으로 맞추지 않는다). 화면도 같은 규칙으로 체크를 맞춘다 —
보기를 끄면 넷 다 끄고, 수정을 끄면 삭제도 끈다. 그래서 화면이 보내는 값은 늘 이미 맞춰진 값이고, 서버의 맞추기는 안전망이다.

### 누가 무엇을 하나

`P` = 그 레코드의 `partId`, '권한' = 내가 `P` 에 속한 소속의 체크(속하지 않으면 다 꺼짐), '관리자' = 그 프로젝트 관리자 · 시스템 관리자.
**관리자는 파트와 상관없이 다 된다.** `P` 가 `null`(공통)이면 **예전 규칙 그대로**다.

| 일 | `P` 가 `null`(공통) | `P` 가 있음 |
| --- | --- | --- |
| 작업 등록 — `POST .../tasks` · `POST .../tasks/batch`(챗봇 초안 포함) · 회의록 반영의 작업 | 누구나(프로젝트 멤버) | 관리자 · `P` 의 **등록**. `P` 는 상위를 따른 **뒤의** 파트다(키를 안 보내면 상위 작업의 파트) |
| 작업 고치기 — `PATCH /api/tasks/{taskId}` · `move` · 본문 줄 · 안건 링크 걸기 · 떼기 · 영향도 반영 | 생성자 · 담당자 · 관리자 | 관리자 · **담당자** · `P` 의 **수정** — 등록만 한 사람은 수정 권한 없이는 못 고친다 |
| 작업 파트 옮기기 — `PATCH` 의 `partId` 를 다른 파트 `Q` 로 | — | 위 고치기 권한에 더해 관리자 · `Q` 의 **수정**. `null`(공통)로 빼는 것은 고칠 수 있으면 된다 |
| 작업 지우기 — `DELETE /api/tasks/{taskId}`(후손 하나하나도 같은 규칙) | 생성자 · 관리자 | 관리자 · `P` 의 **삭제**(담당자는 여전히 못 지운다) |
| 테스트 등록 — `POST .../tests` | 누구나 | 관리자 · `P` 의 **등록**(상위 테스트를 따른 뒤) |
| 테스트 고치기 — `PATCH /api/tests/{testId}` · `POST …/status` · 태그 `PUT` · `DELETE …/refs/…` · `POST …/basis` · 영향도 반영 | 누구나(예전 그대로) | 관리자 · **담당자** · `P` 의 **수정**. 파트를 다른 파트 `Q` 로 옮기면 `Q` 의 **수정**도 |
| 테스트 지우기 — `DELETE /api/tests/{testId}` | 만든 사람 · 관리자 | 관리자 · `P` 의 **삭제** |
| 댓글 · 조치 내역(작업 · 테스트) | 예전 그대로 | 예전 그대로 — 파트 권한을 안 본다 |
| 안건 전부 | 예전 그대로 | 예전 그대로 — 파트 권한을 안 본다 |

- 고치기는 **고치기 전** 레코드로 본다(작업 · 안건과 같다) — 담당자를 남에게 넘긴 뒤의 모양으로 보지 않는다
- 걸리면 403 `FORBIDDEN`. message —
  등록 `이 파트에 작업을 등록할 권한이 없습니다.` · `이 파트에 테스트를 등록할 권한이 없습니다.`,
  옮겨 갈 파트 `옮길 파트에 작업을 고칠 권한이 없습니다.` · `옮길 파트에 테스트를 고칠 권한이 없습니다.`,
  그 밖(고치기 · 지우기) `권한이 없습니다.`(후손 때문이면 `지울 수 없는 하위 작업이 있습니다.` 그대로)
- 일괄 등록은 **모든 줄을 넣기 전에** 본다 — 걸린 줄을 다 `detail` 에 `tasks.N.partId` 로 싣고 아무것도 안 넣는다(`parentTempId` 로 앞 줄의 파트를 따라간 줄도 본다)
- 영향도 반영은 줄마다 그 작업 · 테스트의 고치기 권한 — `detail` 은 `tasks.N` · `tests.N`(`impact.md`). 연결만 하는 테스트 줄(태그)도 같다
- 보관한 파트도 규칙은 같다 — 그 파트 소속의 권한으로 옛 작업 · 테스트를 고친다
- 권한은 요청마다 그 프로젝트에서의 내 소속을 한 번 읽어 본다(`access.Scope.part_rights`, 관리자는 안 읽는다). 판정은 `server/app/services/access.py` 한 곳

### 화면 (프론트가 하는 것)

- 볼 파트 고르기의 **'내 파트'** = 내가 **보기**를 가진 파트
- 작업 · 테스트 · 리스크 메뉴는 **내가 볼 수 있는 파트로 거른 채** 연다(볼 파트가 없으면 전체). **안건 목록은 전체로** 연다 — 위 '볼 파트 고르기 (2026-11-11)' 의 '처음은 누구나 전체' 를 작업 · 테스트 · 리스크에서 갈음한다
- 파트 관리 화면은 사람마다 체크 넷 — 위 '맞추기' 를 화면도 한다(보기를 끄면 넷 다 끔, 수정을 끄면 삭제도 끔). 사람을 더하면 기본값(보기 · 등록 · 수정 켬, 삭제 끔)
- 권한이 없는 단추를 숨기거나 막는 것은 화면의 몫이고, 서버는 위 표로 다시 막는다

## 테이블

```
part          id · project_id → project(cascade) · name · active · created_at
              unique(project_id, name) · unique(id, project_id)   ← 복합 FK 가 참조할 자리
part_member   part_id → part(cascade) · member_id → member · created_at
              · can_view · can_create · can_update · can_delete   (boolean not null, 2026-11-12)
              pk(part_id, member_id)
task.part_id    null 가능. FK (part_id, project_id) → part(id, project_id)
agenda.part_id  null 가능. FK (part_id, project_id) → part(id, project_id)   (2026-11-04 thread → agenda)
```

- 파트는 **같은 프로젝트**의 것만 단다 — 부모 · 링크와 같은 방식(복합 FK · `decisions.md` Q13 · Q16)
- **이행 `0040_part_rights`** — 있던 소속은 넷 다 켠다(지금 하던 일이 그대로 되게 — 지우기는 생성자에서 그 파트 사람 모두로 넓어진다). 열의 기본값은 보기 · 등록 · 수정 `true`, 삭제 `false`(새 소속의 기본값과 같다)
- 사람을 프로젝트에서 빼면(`DELETE /api/projects/{projectId}/members/{memberId}`) 그 프로젝트 파트들에서도 같이 빠진다
- **확장 규칙** — 파트에 매달리는 새 엔티티(테스트 케이스 · 테스트 실행 …)는 `part_id` 를 같은 복합 FK 로 달고,
  위 보기 규칙에 같은 모양(공통 · 내 파트 · 담당 · 링크)으로 들어간다

## 모양

```ts
export interface Part {
  id: string
  projectId: string
  name: string
  /** false 면 보관 — 새 작업 · 안건에 고를 수 없고 관리 화면에서 접힌다 */
  active: boolean
}

/** 2026-11-12 — 소속의 권한. 서버가 삭제 ⇒ 수정, 등록 · 수정 ⇒ 보기로 맞춘 값이다 */
export interface PartRights {
  canView: boolean
  canCreate: boolean
  canUpdate: boolean
  canDelete: boolean
}

export interface PartMember extends PartRights {
  partId: string
  memberId: string
}

/** PUT /api/parts/{partId}/members/{memberId} 의 본문(선택) — 보낸 것만 바뀐다 */
export type PartMemberInput = Partial<PartRights>

// 늘어나는 필드
interface Task   { partId: string | null }
interface Agenda { partId: string | null }   // 2026-11-04 전 Thread

// ProjectSnapshot 에 키 둘이 는다
interface ProjectSnapshot { parts: Part[]; partMembers: PartMember[] }
```

- `parts` 는 이름 순(보관 포함), `partMembers` 는 `(partId, memberId)` 순
- `partId` 는 **`null` 을 낼 수 있는 이름에 더해진다**(`snapshot.md` '빈 값은 `null` 이 아니다' 의 목록에 `partId` 를 더한다)

## 엔드포인트 — 쓰기는 프로젝트 관리자 · 시스템 관리자 (그 밖은 403 `FORBIDDEN`)

| 메서드 | 경로 | 하는 일 | 응답 |
| --- | --- | --- | --- |
| POST | `/api/projects/{projectId}/parts` | `{ name }` 파트 만들기. 이름은 앞뒤 공백을 떼고 1 ~ 50자. 같은 프로젝트에 같은 이름(보관 포함)이 있으면 409 `PART_NAME_TAKEN` | `Part` · 201 |
| PATCH | `/api/parts/{partId}` | `{ name?, active? }` — 이름 바꾸기 · 보관 · 되살리기. 없는 파트는 404 `PART_NOT_FOUND` | `Part` |
| PUT | `/api/parts/{partId}/members/{memberId}` | 파트에 넣기 · **권한 바꾸기** (멱등). 본문은 선택 — `{ canView?, canCreate?, canUpdate?, canDelete? }`(2026-11-12). 새 소속이면 안 보낸 것은 보기 · 등록 · 수정 `true`, 삭제 `false`. 있던 소속이면 안 보낸 것은 그대로, 보낸 것만 덮어쓴다. 그다음 '맞추기'. 본문이 없으면 새 소속은 기본값, 있던 소속은 그대로. `null` 은 422. 그 프로젝트에 부여되지 않은 사람은 400 `MEMBER_NOT_IN_PROJECT` | `PartMember` |
| DELETE | `/api/parts/{partId}/members/{memberId}` | 파트에서 빼기 (멱등) | 204 |

읽기는 스냅샷 한 방이다 — 따로 `GET` 을 두지 않는다. 파트 경로도 프로젝트 경계 검사(`require_scope`)를 그대로 탄다.

### 이미 있는 API 에서 바뀌는 것

| 자리 | 바뀌는 것 |
| --- | --- |
| `POST .../tasks` · `POST .../tasks/batch` | `partId` 를 받는다. **키를 안 보내면 상위 작업의 `partId` 를 따른다**(최상위면 `null`). `null` 을 보내면 공통. 일괄 등록은 배열 순서대로 이 규칙을 적용한다 — 챗봇 초안은 `partId` 를 안 실으니 부모를 따른다 |
| `PATCH /api/tasks/{taskId}` | `partId` 를 바꾼다(`null` 로 공통). **하위 작업은 따라 바뀌지 않는다** — 필요하면 화면이 하나씩 바꾼다 |
| `POST .../agendas` · `PATCH /api/agendas/{agendaId}` (2026-11-04 전 `threads`) | `partId` 를 받는다. 등록에서 안 보내면 `null` |
| 위 전부 | 이 프로젝트의 파트가 아니면 400 `PART_NOT_FOUND`, **새로** 다는 파트가 보관이면 400 `PART_ARCHIVED`. 이미 달린 보관 파트를 그대로 두는 수정은 막지 않는다 |
| `GET .../snapshot` | `parts` · `partMembers` 가 는다. `Task` · `Agenda` 에 `partId`. `PartMember` 에 권한 넷(2026-11-12) |
| 작업 · 테스트 쓰기 전부 (2026-11-12) | 파트가 달렸으면 그 파트의 권한을 탄다 — '파트 권한 (2026-11-12)' |
| `DELETE /api/projects/{projectId}/members/{memberId}` | 그 프로젝트 파트들의 `part_member` 도 지운다 |

## 시드 · 목업 (양쪽이 같은 값을 쓴다)

p1(한화손보 차세대)에 파트 셋. **id 를 이대로 쓴다.**

| id | 이름 | 사람 | 작업 | 안건 |
| --- | --- | --- | --- | --- |
| `pt1` | 인프라 | u3 | k4 · k19 · k20 · k21 · k22 | t1 · t2 · t4 |
| `pt2` | AI | u1 · u4 | k6 ~ k16 | t3 · t7 · t8 |
| `pt3` | 기간계 연동 | u2 | k18 | t5 |

시드 소속은 **권한 넷 다 켬**(이행이 있던 소속을 둔 모양과 같다).
나머지(k1 ~ k3 · k5 · k17 · t6 · t9 · t10)는 공통(`null`). p2 · p3 에는 파트가 없다(전환이 숨는 경우).
u2 는 공통 작업 k3 와 AI 파트 작업 k15 의 담당자다 — '내가 담당자' 규칙이 보이는 예다.

## 화면 (프론트가 정할 것의 테두리)

- 머리글 또는 목록 위에 **[내 파트 | 전체]** 전환 — 작업 세 탭 · 안건 목록이 같이 따른다
- 작업 · 안건 등록과 속성 칸에 **파트 고르기**(공통 + 활성 파트). 하위 작업 추가는 상위의 파트가 골라진 채 연다
- 목록 행 · 카드에 파트 칩(공통이면 안 그림). 작업 목록 조회 조건에 파트 거르기
- **파트 관리**(`/admin/projects/:projectId/parts?part=<id>`) — 왼쪽 파트 목록(만들기 · 보관은 접어서) · 오른쪽 고른 파트(이름 · 보관/되살리기 · 사람 빼기 · 여럿 찾아 더하기 · 그 파트로 걸러진 작업 · 안건 목록 링크) · 사람마다 **보기 · 등록 · 수정 · 삭제 체크**(2026-11-12)
