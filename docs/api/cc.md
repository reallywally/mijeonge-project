# 참조(cc) — 안건 · 테스트 (2026-11-05)

안건과 테스트는 **담당자 1명 + 참조 여럿** 으로 둔다. 담당자는 책임지는 사람(권한 · 리스크 · 거르기의 기준),
참조는 **알아야 하는 사람**이다. 참조는 보기 · 알림용이고 권한을 주지 않는다. 이 파일이 참조 계약의 정답이다.

## 정해 둔 것 (사용자, 2026-11-05)

| | 결정 |
| --- | --- |
| 담당자 | 그대로 **1명**(`ownerId`) — 멀티 셀렉트로 바꾸지 않는다 |
| 참조 | 안건 · 테스트에 `ccIds: string[]` 를 더한다. 그 프로젝트의 활성 멤버, 겹치지 않게, 고른 순서대로. 담당자와 같은 사람도 받는다(막지 않는다) |
| 권한 | 참조는 **권한을 주지 않는다** — 고치기 · 지우기 규칙 그대로. 참조를 바꾸는 것은 PATCH 라 같은 규칙 |
| 리스크 | 참조는 리스크 '사람별' · 신호 어디에도 **세지 않는다** |

## 모양

```ts
// Agenda · TestCase 에 같이
ccIds: string[]          // 빈 값은 []. 고른 순서

// AgendaInput · TestCaseInput (POST)
ccIds?: string[]         // 기본 []

// AgendaPatch · TestCasePatch (PATCH)
ccIds?: string[]         // 통째로 갈아끼운다. null 422
```

- 검사 — 멤버가 아니거나 활성이 아니면 400 (안건 `AGENDA_CC_NOT_FOUND`, 테스트 `TEST_CC_NOT_FOUND`, `detail` 에 그 id). 겹친 id 는 앞의 하나만 남긴다
- 스냅샷의 안건 · 테스트에 `ccIds` 가 실린다
- DB — `agenda_cc(agenda_id, member_id, sort_order)` · `test_cc(test_id, member_id, sort_order)`, PK `(…_id, member_id)`. 리비전 `0033_cc`

## 변경 이력

- 안건(`agenda_history`) · 테스트(`test_history`) 에 칸 `ccIds` — `from` · `to` 는 id 배열(고른 순서). 같은 집합 · 같은 순서면 안 남긴다
- 칸 순서 — 안건은 `ownerId` 바로 뒤, 테스트도 담당자 바로 뒤
- 화면 칸 이름 '참조'. 이행 전 옛 안건 이력의 `ccIds` 줄도 이제 그대로 그린다

## 따라 바뀌는 기능

| 기능 | 바뀌는 것 |
| --- | --- |
| 확인 요청 (`check.md`) | 받는 사람 = **① 연결 작업 담당자(작업 seq 순) ② 안건의 참조(`ccIds` 순)**. 겹치면 처음 자리 하나, 누른 사람은 뺀다, 활성 멤버만. 나머지 규칙 그대로 |
| 안건 목록 | 거르기에 **'나를 참조'** 를 더한다(담당자 거르기 옆, 켜면 내가 `ccIds` 에 있는 것만). 목록 줄에 참조 수(있을 때만 '참조 N') |
| 테스트 목록 | 같은 '나를 참조' 거르기 |
| 상세 · 등록 | 속성 패널의 담당자 바로 아래 **참조** 칸 — 멤버를 여럿 고르는 칩 목록(고른 사람 칩 · × 로 빼기 · '+ 참조' 로 더하기). 안건 등록 다이얼로그 · 테스트 등록에도 같은 칸 |
| 챗봇 (`chat.md`) | `get_agenda` 결과에 참조 이름들 |
| 회의록 AI 정리 | 바꾸지 않는다(참조는 사람이 고른다) |

## 시드 · 목업

서버 시드와 `web/src/fixtures` 는 값 · 순서까지 같게. 참조는 **t2 = [u2, u4], t1 = [u1], tc2 = [u3]**, 나머지는 `[]`.
이력에는 참조 줄을 따로 만들지 않는다(등록 때부터 있던 것으로 본다).

## 구현에서 메운 것 (2026-11-05, 서버)

계약이 비워 둔 자리는 이렇게 정했다. 화면이 불편하면 새 Q 로 다시 연다.

- **이미 걸린 참조는 통과 (Q68 닫힘)** — 지금 참조에 걸려 있던 사람은 그 뒤 비활성 · 부여 해제가 됐어도 PATCH 에 그대로 둘 수 있다(순서를 바꿔도 된다). 400 은 **새로 더한** id 가 그 프로젝트의 활성 멤버가 아닐 때만 — 담당자(Q30) · 파트 검사와 같다. 그런 사람은 확인 요청을 보낼 때 조용히 빠진다(`check.md`). 화면은 흐린 칩으로 보이되 사람이 × 로 뺄 때만 뺀다
- **`detail`** — `{ "ccIds": "<처음 걸린 id>" }` 하나. '처음' 은 겹친 것을 걸러 낸 뒤 보낸 순서로 처음. message 는 `참조할 사람을 찾을 수 없습니다.`
- **검사 순서** — 안건: 프로젝트 → 담당자 → 파트 → 참조. 테스트: 모양(422) → 기간 → 상위 → 담당자 → 참조 → 파트 → 태그. PATCH 에서 참조가 400 이면 아무것도 안 바뀐다
- **개수 상한은 두지 않는다** — 옛 `thread_cc` 의 20명은 되살리지 않았다. 활성 멤버만 받고 겹친 것을 합치니 프로젝트 멤버 수를 넘지 못한다
- **`null`** — 등록 · PATCH 모두 422 `VALIDATION_ERROR`(`detail` `ccIds`). 비우기는 `[]`
- **같은 값** — 겹친 것을 합친 뒤 지금과 같은 사람 · 같은 순서면 줄을 손대지 않고 이력도 안 남긴다. 순서만 바뀌어도 이력은 남는다
- **등록 이력** — 참조를 같이 골라 등록해도 `created` 한 칸뿐이다(안건 · 테스트 다 — 칸으로 나누지 않는 지금 규칙 그대로)
- **테스트 기준(`basis_seq`)** — **`ccIds` 만 보낸 PATCH 는 기준을 다시 찍지 않는다.** 참조를 고친 것은 테스트 내용을 다시 본 것이 아니라서 '기준 바뀜' 신호를 지우면 안 된다. 다른 칸을 같이 보내면 지금처럼 다시 찍는다(`test.md` '새로 찍는 때')
- **지우기** — 안건은 논리 삭제라 참조 줄이 남고 어디서도 안 보인다. 테스트는 하드 삭제라 참조 줄도 같이 지운다(cascade)
- **회의록 반영** — 새 안건은 참조 `[]`, `updates` 는 참조를 건드리지 않는다
- **챗봇 `get_agenda`** — `agenda.ccIds` 에 더해 `ccNames: string[]`(같은 순서의 이름)을 싣는다. 리스크 AI 요약의 근거에는 싣지 않는다
- **받을 사람 없음 메시지** — "받을 사람이 없습니다. 연결 작업에 담당자를 정하거나 참조를 더해 주세요." (`code` 는 그대로 `CHECK_NO_RECIPIENTS`)
- **리비전 `0033_cc`** — 빈 표 둘만 세운다. 있던 안건 · 테스트는 `[]` 로 시작하고, 0032 가 지운 옛 `thread_cc` 줄은 되살리지 못한다. downgrade 는 두 표를 지운다
